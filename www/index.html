webserv

A tiny HTTP/1.1 server written in C++98 for the 42 curriculum. This page exercises every feature from a real browser. Open the developer tools network tab to read the actual status codes and headers.

Static files and MIME types

  • /about.html 200 served as text/html
  • /style.css 200 served as text/css — the styling of this page proves it
  • /uploads/hello.txt 200 served as text/plain from a different root

Directories: index and autoindex

  • / 200 resolves index.html, autoindex is off
  • /uploads/ 200 no index file, autoindex is on → generated listing
  • /private/ 403 no index, autoindex off

Redirection

  • /old 301 the browser follows Location: back to /

Error pages

  • /nope.html 404 custom page from error_page 404 /errors/404.html

The / location only allows GET. Posting to it must be refused.

Expected: 405 Method Not Allowed with an Allow: GET header.

Upload (POST)

The encoding every browser uses for file uploads.

Expected: 201 Created and the list of files written to ./www/uploads.

A raw body, with the target name taken from the URL instead of a part header.

Expected: 201 Created, and ./www/uploads/notes.txt now holds the raw body.

After either upload, browse /uploads/ to see the result.

DELETE

HTML forms can only send GET and POST, so this one uses fetch.

Expected: 204 No Content if the file exists, 404 if it does not, 403 on a directory.

CGI

  • /cgi-bin/hello.py?name=jean&id=42 200 Python, GET, echoes QUERY_STRING
  • /cgi-bin/hello.php 200 PHP, needs php-cgi installed
  • /cgi-bin/hello.cgi 200 compiled C, run cc -o www/cgi-bin/hello.cgi www/cgi-bin/hello.c first, otherwise 404
  • /cgi-bin/guestbook.py 200 guestbook: GET lists, POST writes and deletes, shows REMOTE_ADDR, redirects with 302

POST sends the body on the script's stdin and it is echoed back.

Expected: 200, with REQUEST_METHOD = POST and the body printed back.

Virtual hosts and multiple ports

  • localhost:9090 a second listening socket, autoindex on at the root
  • http://site-b.local:8080/ same socket as this page, different server_name. Add 127.0.0.1 site-b.local to /etc/hosts first, then it serves ./www-b.

What a browser cannot test

These need curl, because the browser normalises or refuses to send them.

  • Body over the limit → 413: head -c 20000000 /dev/zero > big.bin && curl -T big.bin http://localhost:8080/uploads/big.bin
  • Chunked request body: curl -H 'Transfer-Encoding: chunked' -d @Makefile http://localhost:8080/cgi-bin/hello.py
  • Path traversal → 403: the browser resolves .. before sending, so use curl --path-as-is 'http://localhost:8080/../CLAUDE.md'
  • Unknown method → 501: curl -X PATCH http://localhost:8080/
  • Unsupported version → 505: printf 'GET / HTTP/2.0\r\nHost: x\r\n\r\n' | nc localhost 8080
